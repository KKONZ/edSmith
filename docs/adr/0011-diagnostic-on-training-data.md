# Chief Examiner Diagnostic Access to Training Feedback

The Chief Examiner receives the full training feedback DataFrame for the current iteration and uses it to produce a `DiagnosticReport` before proposing any changes. The diagnostic may call linguistic tools (`grammar_check`, `aoa_stats`, `complexity_stats`) to audit feedback quality against objective signals. The `DiagnosticReport` includes per-component issue summaries, a metric snapshot, and structured linguistic findings. It is bundled into the `HumanReviewProposal` shown to the human before any policy or strategy update is applied.

**Why:** Aggregate metrics tell you the score is wrong; they do not tell you why the Feedback is wrong. A model that consistently over-predicts Band 7 for lexical resource could be doing so because the Examiner is using overly generic feedback, missing vocabulary complexity signals, or following ambiguous policy instructions. Only by reading the Feedback text and comparing it against linguistic measurements can the Chief Examiner distinguish these cases and propose a targeted fix — a `StrategyGuidance` change (activate `use_aoa`, focus a specific component) rather than a blind `PromptPolicy` text edit.

**Test set purity preserved:** The Chief Examiner inspects individual feedback records only from the training and validation splits, consistent with ADR 0006. Aggregate test set statistics are included in `metric_summary` for orientation, but no individual test records are passed to the diagnostic. This invariant is enforced by the `run_chief_examiner` MCP tool.

**Considered alternatives:** Passing individual validation records for record-level inspection was considered. Rejected: validation records are a fixed sample carved before Session 1; using them for record-level inspection risks the same implicit benchmark leakage that ADR 0006 guards against for the test set. Training feedback records are the appropriate diagnostic surface because they are already consumed by the fine-tuning step and carry no purity risk.
